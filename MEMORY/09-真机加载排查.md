当前是**手工替换 TweakInject 里的 dylib** 做二分，不是每次重打 deb：

- 结论：**最终验证通过后必须重新打 deb**，把 `PetDFY2`（或修正后的 PetDFY）和素材一起封进去。

## 7. build.047：真正根因（2026-11-25 13:50）

### 7.1 直接证据

用 python 直接 `dlopen` 安装后的 dylib，拿到 dyld 原始错误：

```text
symbol not found in flat namespace '__PDAIImageRetryAllowed'
```

解析 arm64e 切片的 `LC_DYLD_CHAINED_FIXUPS` import 表，flat-lookup 共 13 项：

- 9 项 AX / IOHID（SpringBoard 有，能解析）
- 3 项本工程符号，只有声明没有实现：
  - `__PDAIImageRetryAllowed`（PDChatService.m:297）
  - `__PDAIRequestBody`（PDChatService.m:697）
  - `__PDAIToolDeclarations`（PDChatService.m:696）

build.046 补的 8 个 `PDAI*` 不包含这 3 个，所以绑定失败 → dlopen 返回 NULL → ellekit 静默跳过 → constructor 不执行。

### 7.2 修复

新增 `src/Sources/PDAIMissingSymbols.m`：

- `_PDAIToolDeclarations()` → `PDDeviceToolDeclarations()`
- `_PDAIImageRetryAllowed(e,r,s)` → 读 `AIImageRetry` 偏好，默认 YES
- `_PDAIRequestBody(p,h,t,o,d,err)` → 组装 OpenAI Chat Completions `NSURLRequest`
  （AIBaseURL / AIModel / AIAPIKey / AIExtraHeaders）

### 7.3 本地构建链（重要）

设备上有完整 Theos + OLLVM：

```text
/var/mobile/Library/Application Support/CodexApp/PreparedRuntimes/TheosRuntime/theos
/var/containers/Bundle/Application/3AC47FFE-.../CodexApp.app/ManagedRuntimes/ollvm/bin/clang
```

踩到的坑与绕过：

1. TheosRuntime 二进制不能在沙箱内直接执行 → 把 make/ld64/lipo 等复制到 jbroot 的 `usr/local/tb`，配 `DYLD_LIBRARY_PATH`。
2. THEOS 路径含空格 → 软链 `usr/local/tb/theos`。
3. SDK 只有 `iPhoneOS16.5.sdk` → 建 `iPhoneOS.sdk` 软链。
4. clang 找不到 ld → `ld`/`ld64` 放进 PATH。
5. **keepsmile 的 ldid 只认相对路径**（绝对路径被 RootHide 重定向）→ ldid 一律 `cd` 到目标目录后用文件名。
6. Theos 的签名步骤用绝对路径调 ldid，必然失败 → `make TARGET_CODESIGN=true TARGET_CODESIGN_FLAGS=`，链接完再手工 `cd` + `ldid -S`。

### 7.4 打包坑：Sileo 爆红

失败包 control/data tar 里有 1148 个 `x`（PAX）头，设备 dpkg 报：

```text
unsupported PAX tar header type 'x'
```

原因：用 Python `tarfile` 默认 PAX 格式重打包。build.047 改为 `tarfile.USTAR_FORMAT`，data.tar 只有 `0`/`5` 两种头，设备 dpkg 安装成功。

## 9. 安全模式根因（build.048 之后确认）

### 9.1 复现

用 arm64e 目标编译最小块拷贝测试：

```objc
__weak NSObject *w = o;
Blk b = ^{ (void)w; };
Blk c = [b copy];
```

- 加 `-mllvm -irobf -mllvm --irobf-cse`：arm64e 运行时 **Bus error**，与 SpringBoard 崩溃同型。
- 不加上述参数：正常。

### 9.2 根因

CodexApp 的构建环境通过环境变量给 Theos 注入编译参数：

```text
ADDITIONAL_CFLAGS=-mllvm -irobf -resource-dir .../ollvm/lib/clang/23
CA_OLLVM_ARM64_CFLAGS=-mllvm --irobf-cse
CA_OLLVM_ARM64E_CFLAGS=-mllvm --irobf-cse
```

OLLVM 的 `-irobf` / `--irobf-cse` 会破坏 arm64e 的 block copy helper 指针，导致 `_Block_copy` 跳转到 `0x0000000dac11050` 这类非法地址。

### 9.3 本地构建正确姿势

```sh
unset ADDITIONAL_CFLAGS CA_OLLVM_REQUIRED CA_OLLVM_ARM64_CFLAGS \
      CA_OLLVM_ARM64E_CFLAGS CA_OLLVM_FLAGS
```

Theos 的 merge 步骤在本机会失败（`.unsigned` 不生成），因此：

1. `make` 编译出 `arm64/`、`arm64e/` 两个独立 dylib（忽略最后 merge 报错）；
2. 手动 `lipo -create` 合并；
3. `cd` 到产物目录后 `ldid -S 文件名`（ldid 只认相对路径）。

### 9.4 验证手段

编译 arm64e 的 host 程序，`dlopen` 目标 dylib 后直接调 `[PDOverlayController sharedController]`、`start`：

```text
dlopen ok
instance 0x...
start returned
lastError=no active scene
```

无崩溃 = arm64e 块拷贝正常。

## 10. build.049 之后：安全模式第二层（块生命周期）

### 10.1 现象

build.049 加载成功，但 SpringBoard 崩溃：

```text
EXC_BAD_ACCESS / SIGBUS at 0x00000000dac11950
-[WNLiveRig .cxx_destruct]
-[WNRenderer setLiveRig:]
-[WNRenderer resetLiveWithScheme:freeGround:]
-[PDOverlayController applyAppearance]
-[PDOverlayController ensureWindow]
```

### 10.2 本地复现

用 arm64e 宿主程序直接 `dlopen` + 调 `WNRenderer`：

- `initWithResourceURL:liveOnly:` 内部会 `resetLiveWithScheme:`；
- 再调一次 `resetLiveWithScheme:` → 释放旧 rig → SIGBUS；
- 单独 `create rig → render → step` 也会在第二次 `render` 崩。

### 10.3 根因

`wn_install()` 把 **栈上 block** 传给 `-[WNLiveRig warp:function:]`，后者直接存进字典：

```objc
_warps[name] = fn;      // fn 是栈 block
```

栈 block 不会随字典 retain 被拷贝；函数返回后栈帧复用，字典里留下野指针。第二次 render 覆盖该键、或 rig dealloc 释放字典时，就 SIGBUS。

### 10.4 修复

```objc
- (void)warp:(NSString *)name function:(id)fn {
    if (![name isKindOfClass:[NSString class]]) return;
    if (fn) _warps[name] = [fn copy];   // Block_copy
    else [_warps removeObjectForKey:name];
}
```

### 10.5 验证（arm64e 宿主程序）

- 3 次 reset + 5 次 step + render + holdFace：全部通过；
- rig 释放（dealloc）：通过。

## 19. 原版 0.1.7 / 1.2 对比：draw 信号量应是非阻塞 → build.062

### 19.1 原版信息

### 19.2 原版 `-[WNRenderer drawInMTKView:]`（0x5f340）

```asm
0x5f43c  bl dispatch_semaphore_wait
0x5f440  cbnz x0, 0x5fac4        ; 非 0（拿不到槽）直接跳到结尾
```

`mov x1, 0` → timeout = **DISPATCH_TIME_NOW**，即**非阻塞**。拿不到槽就跳过本帧。

一旦槽位不可用，主线程每帧阻塞 0.5 秒 → 看门狗 60 秒 → 卡死/安全模式。

```asm
objc_opt_new → _uploadSurfaces (+0x100)
objc_opt_new → _livePositionBuffers (+0x110)
objc_opt_new → _multisampleTargets (+0x140)
```

我们已补齐 `_frameSlots`（3 个初值 1 的信号量）。

### 19.4 build.062 修复

1. `dispatch_semaphore_wait(slot, DISPATCH_TIME_NOW)`：非阻塞，拿不到槽直接 pop pool + return。

## 23. build.065 装机后：角色出现但 UV 错位/不能交互 → build.066

### 23.1 现象

- 角色区域 82×82 出现（纹理已加载，有衣服/头发颜色）；
- 但内容像压扁/横向碎片；
- 不能点击、不能拖动、不移动、不发声。

### 23.2 根因

1. **UV 顺序错位**：
   - `compileMesh` 生成顶点：外层 `i`（行/y），内层 `j`（列/x），即行优先；
   - `meshesForParts` 索引：`v00 = row * stride + col`，也是行优先；
   - 但 UV 循环写成了外层 `j`（列/u）、内层 `i`（行/v），列优先。
   - 结果：每个顶点采到别的 texel → 角色像压扁/碎片。

2. **delegate 设错**：
   - `PDPetView.initWithResourceURL` 里 `self.delegate = _renderer`；
   - 但 `PDPetView.drawInMTKView:` 才是负责 `updateInteractionRegion`（触摸命中区域）和 `drainSoundEvents`（音效）的转发层；
   - delegate 直接给 renderer 后，这个转发层永远不执行 → 不能点、不能拖、不发声。

### 23.3 build.066

1. `meshesForParts` 的 UV 循环改为行优先（外层 i，内层 j），与顶点/索引一致。
2. `PDPetView.delegate = self`（PDPetView 转发给 renderer），恢复交互区域与音效。

## 24. build.066 装机后：角色正常显示，但无交互/动画/声音 → build.067

### 24.1 现象

截图：紫发女仆角色完整显示（UV 修复生效），但：

- 不能点击；
- 不能拖动；
- 不自动走动；
- 不发声。

### 24.2 根因

1. **命中测试取错路径**：

```objc
if ([self respondsToSelector:@selector(interactionPath)]) {
    hitPath = (__bridge CGPathRef)[self performSelector:@selector(interactionPath)];
}
```

`PDPetView` 没有 `interactionPath` 方法 → `hitPath = nil` → `interactionView.hidden = YES` → `pointInside` 永远 NO。

真正有路径的是 `_renderer.interactionPath`（`buildsInteractionPath=YES` 时生成）。

2. **动画驱动未开**：

```objc
if (([self interactive] || [self playing]) && !dragging) {
    [_liveRig step:step buildMesh:YES];
}
```

`_playing` / `_interactive` 默认 NO，全仓无 `setPlaying:YES` 调用 → `motion.step` 永不执行 → 不走路、不眨眼、无音效事件。

### 24.3 build.067

1. `PDPetView.pointInside`：直接用 `renderer.interactionPath` 做 `CGPathContainsPoint`（stage→view 坐标换算）。
2. `updateInteractionRegion`：用 `renderer.interactionPath` 的包围盒设置 `interactionView.frame`，并 `hidden=NO`。
3. `PDOverlayController.updateVisibility` 显示分支：`[[[self pet] renderer] setPlaying:YES];`。
